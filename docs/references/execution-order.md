依据：[根目录说明](../README.md)、[能力清单](../capabilities.json)、[08计划](../08-workbench-ui/PLAN.md)、[共同合同](development-contract.md)及用户最新优先级。完成后的安装/API验证细节见 [live-installation-plan.md](live-installation-plan.md)。目录编号与现有链接保持不变。

## 1. 顺序与独立交付

固定顺序为 **05 → 07 → 08 → 06 → 03 → 04 → 02 → 01**。每项可以在自己的runtime、fixture与临时profile中独立开发，不要求其他七项全部存在。顺序决定优先投入和真实接入次序，不把单项后端实现变成其余模块的硬依赖。

| 顺位 | 项目与主形态 | 此次轮到它时的独立交付 | 接入08的时点 |
|---|---|---|---|
| 1 | [05本地记忆](../05-local-memory/PLAN.md)：DSH plugin + 本地store | scope/版本/删除/预算闭合的本地记忆、批准Provider提炼、管理入口 | 第3阶段08存在后接入；此前自行提供可用入口，不等待08 |
| 2 | [07上下文](../07-context-management/PLAN.md)：plugin | 只读观察优先，明确实际/估算输入与05注入；压缩独立受控 | 与05一并成为08首批真实模块 |
| 3 | [08工作台](../08-workbench-ui/PLAN.md)：最小bundle + profile | 独立框架、manifest/兼容/冲突/卸载诊断，并接已验收05/07 | 本阶段即可形成首个可交付工作台，不等待其余五项 |
| 4 | [06本地图示](../06-local-diagrams/PLAN.md)：按需skill/plugin | 本地呈现；生成与编辑分离，证据不变成事实 | 单项门禁通过后追加，不重装整个聚合生态 |
| 5 | [03会话管理](../03-session-management/PLAN.md)：Host/client plugin | 基础管理及明确覆盖范围的回退、journal/outbox | 追加会话入口，并核05失效/07上下文影响；不假定跨模块原子事务 |
| 6 | [04代码学习](../04-code-learning/PLAN.md)：学习skill + Atlas适配 | 真实Kbuild/compdb下的单/多仓证据阅读、预测/续读；Viewer后置 | 必要时链接本地学习产物；可消费03事件，不要求03服务在线才独立测试 |
| 7 | [02远端环境](../02-remote-environment/PLAN.md)：本地stdio MCP + skill | AutoEnv薄适配、持久交互、装包/测试/日志、按需GDB | 仅接运行状态/本地日志入口，不让UI拥有凭据或远端协议 |
| 8 | [01浏览器认证](../01-browser-auth/PLAN.md)：plugin/provider | 核实真实载体/bridge、同页控制、本地认证引用 | 最后追加浏览器入口；投屏与原内置页分开验收 |

以上是未来交付目标，不表示任何模块已实现或通过运行验证。

## 2. 08排第三：框架先交付，组合持续增长

08既有计划中的“最后真实全组合”只表示最终完整矩阵检查；不再作为08开始或首版交付的前置条件。采用两个层次：

1. **08首版**：先用两个无网络合成plugin验证manifest、版本gate、slot/工具/writer冲突、profile可恢复写入与dispose；再仅装配已经独立验收的05和07。首版具有真实记忆与上下文入口，不用未来模块的假按钮冒充可用能力。
2. **后续增量**：06、03、04、02、01逐项通过单项门禁后，向组件manifest登记并进行一次有针对性的组合验证。08不重新实现它们的存储、索引、凭据、连接与业务状态；最终全组合发生在最后一项接入后。

08沿用现有拟议接口`resolveComposition({hostVersion,capabilities,requestedModules,locks})`、`inspectConflicts(modules)`、`composeProfile({profileRoot,modules,expectedRevision})`。每个真实模块接入至少登记：id、version/source lock、hostRange、需要服务、提供slots/tools/writer、网络能力、dispose及健康状态。缺服务、版本不符、重复writer、未知构件必须诊断为不可启用，不自动补依赖或升级。

未完成模块只列“未安装/未验收”状态或不展示入口；fixture证明装配器可运行，不证明真实模块兼容。05/07未取得接入资格时，08可独立完成框架验证，但真实05/07工作台切片仍标待验证，不能以fake代替交付。

## 3. 每项从计划到安装的同一条门禁

| 门禁 | 必须取得的证据 | 未满足时 |
|---|---|---|
| G0 来源与范围 | 固定代码/包/依赖/许可/摘要、本地runtime、真实宿主与本次scope/Provider用途 | 保留planned/blocked说明，不安装latest或扩大目标 |
| G1 本地行为 | 计划中的真实失败用例→最小实现→通过验证；故障恢复、路径/scope、秘密金丝雀、负向出口 | 修复边界，不能因正向功能可用而条件放行 |
| G2 隔离集成 | 临时DSH_HOME/profile与合成会话/数据；真实Host加载/卸载、重启及Provider替身合同；核进程树及浏览器子资源，真实已注册API请求在G4 | 标集成未验证，不把unit/fake当Host运行证据 |
| G3 独立评审 | 对实际构件、实现、测试输出、skip/unknown及数据流的独立复查；阻断问题关闭 | 不标为可安装交付 |
| G4 授权安装/API测试 | G0—G3完成后，用DeepSeek Harness安装已锁plugin，复用已注册Provider做合成数据测试 | 失败保留诊断并回到对应门禁，不绕过版本或网络控制 |
| G5 工作台增量 | 08出现后接入该单项，验证与当前已启用模块的真实共存 | 不影响其他独立交付；回退失败组合，保留之前可用profile |

用户已经授权“插件完成后可通过DeepSeek Harness安装并使用已注册API测试”；到G4且范围相同时不重复请求确认，也不把已授权API测试永远推迟。该授权不等于本轮立即安装，不授权未完成原型，不允许为了验证额外引入云服务、导出凭据或读取全部真实历史。

模型请求由宿主批准Provider和本地凭据引用完成，测试代码/界面/日志不读取、回显或复制API key。记忆提取/总结/反思/去重属于已允许模型用途；队列绑定入队时批准route/scope/用途，不从环境其他key、CLI或备用endpoint回退。负向出口必须涵盖模块、Host、子进程、下载器、同步/隧道及浏览器资源，不能只检查源码是否出现fetch。

## 4. 宿主版本与授权不扩大

目前只读确认安装包基线为 **DSH 0.2.1-rc.5**；每次真实接入前重核运行实例/profile，不把另一份0.2.2-alpha.2源码当现用Host。Rewind和web-all调查新版本的门槛高于此基线，不能为顺序或UI需求自行升级、豁免version gate或修改应用归档。先选并验证兼容固定版；确需升级时另形成明确版本、会话格式迁移、备份和恢复方案。

依赖/构建/运行步骤复用既有可信参数和已给授权，不对每次同条件测试重复询问。新增不受控构建脚本、扩大可执行工具链范围、宿主升级、真实历史导入、真实设备/服务器/PID/站点访问或其他超出现有任务的动作，要先明确具体影响并核对是否已有授权；没有时不能从“完成后可安装测试”推导放行。普通本地检查与可逆文档工作不因此新增审批流程。
